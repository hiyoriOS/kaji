---
title: Approval
description: Require an application decision before selected capability executions.
---

Approval adds an application-owned decision between authorization and capability execution.

Kaji does not provide an approval interface, identity system, inbox, policy engine, or notification service.

## Marking requests

Add an `approval` predicate to the capability:

```ts
const refundPayment = capability({
  name: "payments.refund",
  input: RefundInput,
  authorize: ({ principalId, input }) => canRefund(principalId, input),
  approval: ({ input }) => input.amount >= 1_000,
  execute: refundThroughProvider,
});
```

The predicate receives validated input and `principalId`. It returns `true` or `false` synchronously.

When the predicate returns `false`, Kaji continues without an approval request.

## Approval handler

Configure `approve` on the executor:

```ts
const kaji = createKaji({
  store,
  approve: async ({ capability, principalId, input, idempotencyKey }) => {
    return approvalService.request({
      capability,
      principalId,
      input,
      idempotencyKey,
    });
  },
});
```

The handler returns:

```ts
{
  approved: boolean;
  evidence?: unknown;
}
```

The evidence field is optional. Kaji accepts it but does not expose or persist it in `@hiyorios/kaji@0.3.1`.

Your application approval system must retain any evidence that it needs for audit or recovery.

## Fail-closed behavior

Kaji calls the capability only after an explicit `{ approved: true }` decision.

Each of these cases returns `status: "rejected"`:

- no approval handler is configured
- the handler returns an invalid value
- the handler returns `{ approved: false }`
- the handler throws or rejects

The original handler error remains available in `result.error` when applicable.

## Ordering and retries

Authorization runs before approval. An unauthorized request never reaches the approval handler.

Kaji claims the idempotency key before approval. An identical retry returns the recorded rejection or result instead of requesting a second decision.

Your application must decide how long an approval is valid. Kaji does not refresh or revoke approval evidence.
