---
title: Cancellation
description: Cancel requests and set timeouts with AbortSignal.
---

Kaji uses the standard `AbortSignal`. Your `execute` function receives it as `context.signal`. Pass it to anything that can be cancelled:

```ts
execute: async (input, context) => {
  return provider.refund(input, {
    idempotencyKey: context.idempotencyKey,
    signal: context.signal,
  });
},
```

To cancel a request, pass your own signal to `kaji.execute()` as `signal`:

```ts
const controller = new AbortController();
const pending = kaji.execute(refundPayment, { ...request, signal: controller.signal });

controller.abort();
```

## Before execute

If the signal is already aborted before `execute` is called, Kaji returns `cancelled` and `execute` does not run.

## During execute

Kaji cannot stop your function or a remote request. `execute` has to watch `context.signal` itself:

```ts
execute: async (input, context) => {
  context.signal.throwIfAborted();
  return provider.refund(input, { signal: context.signal });
},
```

- If `execute` rejects after an abort, Kaji returns `unknown`, because the action may have already happened.
- If `execute` ignores the signal and finishes, Kaji returns `succeeded`.

An abort does not undo anything and does not prove a remote request stopped.

## Waiting on a duplicate

If the same request is already running, `kaji.execute()` waits for its result. Aborting the signal, or reaching `timeoutMs`, stops the wait and returns `unknown`, not `cancelled`, because the original request may still complete. It keeps running and saves its own result, and retrying with the same key returns it.

## Timeouts

```ts
const kaji = createKaji({
  store: memoryStore(),
  timeoutMs: 30_000,
});
```

`timeoutMs` must be greater than 0 and at most 2,147,483,647 (about 24 days). `createKaji()` throws a `KajiConfigurationError` for any other value.

After `timeoutMs`, Kaji aborts `context.signal`. It does not stop `execute`: Kaji still waits for it to finish. For the timeout to have an effect, your function or the API it calls must watch the signal. If you also pass a `signal` to `kaji.execute()`, whichever aborts first wins.
