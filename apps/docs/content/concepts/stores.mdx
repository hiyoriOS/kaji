---
title: Stores
description: Where Kaji records requests and results, and how to write your own store.
---

Kaji needs a store to remember which requests it has seen and what happened. Pass one to `createKaji()`:

```ts
const kaji = createKaji({ store: memoryStore() });
```

## `memoryStore()`

Keeps records in memory. It is meant for development, tests, and examples. It only works inside one process, and it loses everything when the process exits.

## Writing a store

For production, write a store backed by a database. A store has two methods:

```ts
type ExecutionStore = {
  claim(claim: ExecutionClaim): Promise<ClaimResult>;
  record(execution: StoredExecution): Promise<void>;
};
```

`claim()` is called for every request, right after input validation:

```ts
type ExecutionClaim = {
  readonly capability: string;
  readonly principalId: string;
  readonly idempotencyKey: string;
  readonly inputFingerprint: string;
};

type ClaimResult =
  | { status: "claimed"; executionId: string }
  | { status: "existing"; outcome: Promise<StoredExecution> }
  | { status: "conflict"; executionId: string };
```

- `claimed`: a new request. Kaji goes ahead.
- `existing`: the same request was already made. Return its saved result, or a promise for it if it is still running.
- `conflict`: the same capability, `principalId`, and `idempotencyKey` came with different input (its `inputFingerprint`, a hash of the validated input, differs).

If two callers send the same new request at once, exactly one must get `claimed`. Use a unique constraint or a transaction.

`record()` saves the final result of a claimed request. It must never overwrite a result that is already saved, in particular never replace `unknown` with something else.

## Before going to production

Check that your store:

- claims atomically, so concurrent duplicates get one `claimed`
- is shared by every process that runs the capability
- keeps its records across restarts
- has a plan for how long to keep records

## When the store fails

If `claim()` fails, `kaji.execute()` rejects with a `KajiConfigurationError` and nothing ran. If `record()` fails, you get `unknown`, because the action may already have run.
