---
title: Idempotency
description: Make sure the same request never runs twice.
---

Every request needs an `idempotencyKey`: a unique ID for one intended action.

```ts
await kaji.execute(refundPayment, {
  input: { paymentId: "pay_123", amount: 50 },
  principalId: "user_123",
  idempotencyKey: "refund_pay_123_v1",
});
```

Kaji treats the capability name, `principalId`, and `idempotencyKey` together as the identity of a request.

- **Use one key per action.** Reuse a key only to retry the same action.
- **Same identity and same input:** Kaji returns the saved result, or waits for the one in progress, and does not run `execute` again. This includes a saved `unknown`.
- **Same identity and different input:** Kaji returns `failed` and does not run `execute`.
- **A new action:** use a new key.

## How far this goes

Kaji prevents duplicates through the store you give it. `memoryStore()` only sees requests in its own process and forgets everything on restart. A store that saves to a shared database can cover many processes and restarts, if it claims requests atomically (see [Stores](/docs/concepts/stores)).

Kaji cannot control what an outside service does inside `execute`. If your provider supports idempotency keys, pass it yours:

```ts
execute: (input, context) =>
  provider.refund(input, {
    idempotencyKey: context.idempotencyKey,
    signal: context.signal,
  }),
```
