Kaji validates input with any [Standard Schema](https://standardschema.dev) library, including Zod, Valibot, and ArkType. This guide uses Zod.

## Define a capability

A capability is one action your app can perform, with its input, permission check, and the function that does the work.

```ts
import { capability } from "@hiyorios/kaji";
import { z } from "zod";

const refundPayment = capability({
  name: "payments.refund",
  input: z.object({
    paymentId: z.string().min(1),
    amount: z.number().positive(),
  }),
  authorize: ({ principalId }) => principalId.startsWith("user_"),
  execute: async ({ paymentId, amount }, context) => {
    // Call your payment provider here.
    return { refundId: `refund:${context.idempotencyKey}`, amount };
  },
});
```

## Create a Kaji instance

```ts
import { createKaji, memoryStore } from "@hiyorios/kaji";

const kaji = createKaji({ store: memoryStore() });
```

`memoryStore()` keeps records in memory for one process. Use it for development and tests. In production, use a store that saves to a database (see [Stores](/docs/concepts/stores)).

## Run it

```ts
const outcome = await kaji.execute(refundPayment, {
  input: { paymentId: "pay_123", amount: 50 },
  principalId: "user_123",
  idempotencyKey: "refund_pay_123_v1",
});
```

You supply `principalId` (who is asking) and `idempotencyKey` (a unique ID for this request). Kaji does not generate either one. Retry a request with the same key. Use a new key for a new request.

If the input fails validation, `kaji.execute()` rejects with an `InvalidInputError`.

## Handle the result

```ts
switch (outcome.status) {
  case "succeeded":
    console.log(outcome.result);
    break;
  case "denied":
  case "rejected":
  case "failed":
  case "cancelled":
    console.error(outcome.error);
    break;
  case "unknown":
    // The action started but may or may not have finished.
    // Check your payment provider before retrying.
    await checkRefundWithProvider(outcome.evidence);
    break;
}
```

See [Outcomes](/docs/concepts/outcomes) for what each status means.

## Add approval

Add an `approval` function to say which requests need a person's sign-off, and an `approve` function to ask for it.

```ts
const refundPayment = capability({
  name: "payments.refund",
  input: RefundInput,
  authorize: ({ principalId, input }) => canRefund(principalId, input),
  approval: ({ input }) => input.amount >= 1_000,
  execute: refundThroughProvider,
});

const kaji = createKaji({
  store,
  approve: async (request) => approvalService.request(request),
});
```

If approval is not given, the action does not run. See [Capabilities](/docs/concepts/capability) for details.
