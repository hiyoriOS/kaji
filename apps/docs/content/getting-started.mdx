Kaji accepts any [Standard Schema](https://standardschema.dev) V1 schema as `input`. This guide uses Zod, but Valibot, ArkType, and hand-written schemas work the same way.

## Define a capability

A capability names one application action. It also defines input validation, authorization, optional approval, and execution.

```ts
import { capability } from "@hiyorios/kaji";
import { z } from "zod";

const refunds = new Map<string, number>();

const refundPayment = capability({
  name: "payments.refund",
  input: z.object({
    paymentId: z.string().min(1),
    amount: z.number().positive(),
  }),
  authorize: ({ principalId }) => principalId.startsWith("user_"),
  execute: async ({ paymentId, amount }, context) => {
    refunds.set(paymentId, amount);
    return { refundId: `refund:${context.idempotencyKey}`, amount };
  },
});
```

Kaji validates `input` before it calls `authorize` or `execute`. Invalid input rejects `kaji.execute()`'s promise with `InvalidInputError` instead of resolving to a status; no claim, authorization, approval, or execution happens.

## Create the executor

```ts
import { createKaji, memoryStore } from "@hiyorios/kaji";

const kaji = createKaji({ store: memoryStore() });
```

`memoryStore()` is process-local and non-durable. Use it for development, tests, and examples.

For production, provide an `ExecutionStore` with the durability and coordination that your deployment requires.

## Execute the capability

```ts
const outcome = await kaji.execute(refundPayment, {
  input: { paymentId: "pay_123", amount: 50 },
  principalId: "user_123",
  idempotencyKey: "refund_pay_123_v1",
});
```

The caller must provide `principalId` and `idempotencyKey`. Kaji does not infer either value.

Within one capability and principal, the idempotency key must identify one intended operation. Reuse the same key only for a retry of that operation.

## Handle the result

Extend the switch on `outcome.status` from the call above. `reconcileRefund` is application code that checks the payment provider and the stored evidence to decide what actually happened.

```ts
switch (outcome.status) {
  case "succeeded":
    console.log(outcome.result);
    break;
  case "denied":
  case "rejected":
  case "failed":
  case "cancelled":
    console.error(outcome.error);
    break;
  case "unknown":
    await reconcileRefund(outcome.evidence);
    break;
}
```

Do not blindly retry `unknown`. The side effect can commit before an error reaches Kaji.

Read [Outcomes](/docs/concepts/outcomes) for the exact meaning of every status.

## Add approval

A capability can declare when approval is required. This is a separate, illustrative capability; `RefundInput`, `canRefund`, and `refundThroughProvider` stand in for application-defined validation, policy, and provider code:

```ts
const refundPayment = capability({
  name: "payments.refund",
  input: RefundInput,
  authorize: ({ principalId, input }) => canRefund(principalId, input),
  approval: ({ input }) => input.amount >= 1_000,
  execute: refundThroughProvider,
});
```

Your application supplies the approval handler:

```ts
const kaji = createKaji({
  store,
  approve: async (request) => approvalService.request(request),
});
```

Kaji fails closed. Missing, invalid, rejected, or failed approval prevents capability execution.
